# Brief 07 — the growth engine, simpler · return

*Tour de Growth · Claude Design → the codebase · 2026-10-02 · answers
DS-EXTENSION-BRIEF-07*

The engine keeps everything it knows. What changes is **when** each thing
shows. In five moves:

1. **A returning person is known before the first paint.** One inline
   script asks whether the engine's storage key exists, and the page
   becomes the short version by CSS alone. The tool starts at **287px**
   instead of 1,267px (288px instead of 1,849px on a phone), and nothing
   jumps. Search engines still read the whole first-visit page.
2. **The board is the progress, and it has one next step.** Under the
   verdict, one card (`NextStep`) says what changed since last time and
   offers **one** primary action, picked by a fixed order: start the month,
   the quick numbers, the requests, the long numbers, the slides. The first
   screen on return has **5 controls** at 1280 and **3** at 390. Today the
   board has 75 controls.
3. **The setup asks one question.** "How do you sell?", already answered
   by default. Every other default is said in one sentence, with "Change".
   You reach the first number typed in **2 screens instead of 4**, through
   7 controls instead of 36 + 6 + 2.
4. **One number, one question.** The value boxes are the question. "No
   figure to hand?" leads to the other three answers. The **trap is open
   just above the value**, because it changes what you type. Where to find
   it is one tap away, and its summary names the tools. Reference, target
   and verdict become one object, and the target is asked there, once the
   value is in front of you.
5. **One list of numbers by stage** replaces the five tabs. The requests
   become one step of the journey ("send the requests today, fill in the
   rest while waiting"). "What if?" starts from one lever. The hybrid shows
   one engine at a time under the total.

No synced component is replaced. Two get a small delta each (`Disclosure`,
`BulletChart`). Fourteen engine components are new, and the data model does
not change.

## The twenty answers

### The page and the two visits

**1. Where does a returning person land? → The same URL, already short,
from the first paint.**

The page is prerendered and identical for everyone, so the decision is made
**before the first paint**, not after hydration. `engineKnownScript(key)`
(EngineLanding) is an inline `<head>` script. It only asks whether the
engine's storage key exists: no value is read and nothing is sent. If it
does, the script sets `<html data-engine="known">`. EngineLanding's CSS then
draws the short page:

- the eyebrow, and the H1 at section size;
- **the privacy promise in one line**, never folded;
- the tool.

The positioning, the hero's call to action and the stopwatch are hidden by
CSS: they are still in the HTML. "How long it takes" moves under the tool
for everyone.

**What the page shows in the first instant:** the header, the band, the
eyebrow, the H1, the promise line, then the tool's place held by a dashed
box ("Opening your engine…", `--engine-reserve` tall) until the board
renders (`return-instant`). The box is dashed because dashed means "not
yet". Its height keeps everything above the fold where it is, and only
what is below the fold moves when the board arrives.

- **Search engines** have no storage, so they always read the first-visit
  page: H1, promise, positioning, catalogue, FAQ (constraint 12).
- **Private windows, blocked storage:** the script does nothing, so the
  person sees the first visit, which is right.

**2. The first screen on return → the engine bar, the verdict and
NextStep. Nothing else.**

| | 1280 × 900 | 390 × 844 |
|---|---|---|
| Above the tool | header, band, "The engine", H1, the promise line | same |
| The tool's first screen | EngineBar (line, Settings, the menu), the verdict, NextStep | same, the verdict at 25px |
| Controls | 5 | 3 |
| The primary's bottom edge | 768px | 788px (French 812px) |

The diagnosis, the peloton, the list and the lever follow below. The

| The browser refused to save | Save to a file (.json) → |

| Quick numbers left (5 min) | Next number: {name} → |
| Requests not yet sent | Ask Finance for the CAC → / Copy your 5 requests → |
| Long numbers left (~1 h) | Next number: {name} → |
| Requests pending only, or everything found | Prepare your slides → |

With the brief's "returning" data, every quick number is found and the CAC
has not been asked yet, so the primary is **"Ask Finance for the CAC →"**.
The request to Data shows as a line with "Follow up", and the missing
backup as a line with "Save (.json)".

**3. The bands → one place, NextStep.**

Today four strips each say one thing: next month, resume, backup, and "your
browser refused to save". Now one card does it, in this order: the reason,
the one action, then what else waits.

- **Something pending** (a request out, a month ended) gets a dashed line.
- **Advice** (backup missing, storage refused) gets a dashed red line.
- **The refused save** is the one that takes over the primary, since a
  file is then the only way to keep the work.
- **The backup warning** shows only while it is needed. It is a NextStep
  line, plus the "Never saved" tag in the engine bar, plus the full
  sentence (Safari's seven days) at the end of the menu's File group.

**8. Where to find it, the trap, "also in" → the trap before typing; the

**Yes, the trap belongs before typing.** Every trap in the catalogue is

"Where to find it" stays closed, but **its summary lists the tools** ("GA4
· Mixpanel or Amplitude · Product database"), so a person sees whether

- each tool and its path, word for word, with the person's own tools first;
- "Also in GA4: …", as ink links, each a 44px row.

The open state is `number-open`.

**9. Reference and target → one object, HowItCompares.**

One chart (BulletChart with the `band` delta) draws all three:

- the bar is your figure;
- the red tick is your team's target;
- a bracket **under** the track is the published range.

Under it come one legend line, the caveat word for word, and the target box
itself. "Below target" (Tag alert, the red of a diagnosis) appears **only
against a team target** (C1). A reference never earns a tag, a colour or an
edge. Today's dashed range is gone, because dashed means "not yet".

**10. The two text areas → merged into one closed Disclosure, "Your
definition and a note". Both fields are kept.**

They are optional, and open they cost about 300px on every number. The
definition keeps its hint (it appears in the slides' annex and in the
requests), and so does the note ("Never on a slide"). The trap opens the
Disclosure when it asks for a definition (Disclosure delta).

### The step-by-step

**11. Granularity → one number per screen stays, but ordered by what the
person has at hand, with the requests as one step.**

A number's value and its knowledge belong together. A screen per stage

order and what counts as a screen:

1. the quick numbers (5 minutes each), so the first number is typed two

2. **"To ask for"** (AskList): one screen, one card per role, each with its

pass. That makes 15 screens to the slides instead of 22, and 25 instead of
39 in the hybrid. It is Antoine's own sentence made a rule: *send the
requests today, fill in the rest while waiting.*

in one place, for a team that keeps its targets in a sheet.

Without a target, the board says so plainly: "No stage named: none of the
six numbers that can name one has a target yet", with "Add your targets"

**14. Steps and board: two things or one? → One.**

## The constraints, one by one

1. **Tokens only.** All new values are in `tokens/engine.css`: measures,
   `font` shorthands, and colours by meaning built on existing tokens. There
   is no hex anywhere in the components. The board's own CSS uses tokens
   too, except the site header's measured height (a stand-in).
2. **The system first.** The new screens are built with Button, Card,
   Choices, Checkbox, NumberField, Field, FieldRow, Select, TextArea,
   TextField, Segmented, Disclosure, Tag, MetaLabel, GlossaryTerm, BulletChart
   and DotGrid (the peloton). The 14 new pieces each have a contract
   (`.d.ts`) and usage rules (`.prompt.md`). There are two deltas, no
   replacement and no other synced change. StatTile, DataTable, DateField,
   FormSummary, Callout and StageProfile are not needed. An invalid value
   uses the FieldRow's own error, because one field doesn't need a summary.
3. **AA contrast.** Measured on the real ground (table below). Every text
   is at least 4.5:1 (large red verdict text at least 3:1), and every edge,
   ring and mark at least 3:1.
4. **44px targets, none overlapping.** This is checked by script on all 27
   screens × 2 languages × 3 widths (1280, 390, 320): each control's
   target, including the system's `::before` extensions, is at least 44px
   tall, and no two overlap. The result is 0 issues. Three things came out
   of the check:
   - every NextStep line and menu item is a 44px row;
   - the engine bar's top line is a 44px row;
   - no `?` sits in a label right above a box.
   The site header's language switch is the app's and was not checked.
5. **Red means one of three things.**
   - **Solid red fill: the primary.** One per screen.
   - **Red wash or solid red edge: a diagnosis.** The held-back stage's
     edge, "Below target" and "Holds you back" (Tag alert), the verdict's
     red clause, the diagnosis block.
   - **Dashed red: advice.** The trap, "To repair", the backup and refused
     lines, the window warning in Settings.
   Links are ink, not red.
6. **One loud thing.** One raised card per screen: the promise card on a
   first visit, the peloton on the board, none on a number or in Settings.
   One primary per screen: checked by script on every state (the first
   visit's hero call to action became secondary for this).
7. **One signature effect; dashed means "not yet".** Dashed is used for:
   to do, asked, never saved, the first instant's reserve, a month ended,
   requests out, and the "later" company types. The effort tag and the
   reference range are no longer dashed.
8. **No icons.** The only glyphs are → ← ? and the disclosure's +/−. The
   status marks are the peloton's dots (filled, hatched, ring, dashed ring,
   struck ring). TotalBand has no "+" or "=".
9. **Bilingual from the same component.** Every state is drawn in both
   languages by the same files. French is often longer (« Demander le CAC
   à la finance → ») and still fits the first screen at 390px (812px of
   844).
10. **Local and deterministic.** There is no account, server, e-mail or AI.
    NextStep's choice is a fixed order, and every figure is the engine's
    own calculation. The pre-paint script reads whether a key **exists**,
    not its value, and sends nothing. A request leaves the device only when
    the person copies it. Nothing typed goes in a URL. No analytics event
    is added (if the port counts NextStep clicks, the event carries the
    step's kind only, never a number or a name).
11. **The privacy promise comes before the call to action and never
    folds.** On a first visit it is the card before "Enter your numbers →".
    On a return it is the line before the tool and its NextStep.
12. **Searchable content in the server HTML.** The H1, promise,
    positioning, catalogue and FAQ are always in the HTML. For a returning
    reader, CSS hides the positioning only, and crawlers never get the
    flag.
13. **From 320px, no horizontal scroll.** Checked on every state at 320,
    390 and 1280: 0 overflows. There is one column for the whole tool
    (`--engine-measure`, 720px).
14. **The keyboard.** A number's screen is a `<form>`, so Enter in any box
    saves ("Save and continue →" is its submit). Focus moves to the
    number's heading when a person moves to it (a row, NextStep, Save and
    continue), and never on first paint. Disclosures stay native
    `<details>`.
15. **The data stays. No change to the model.**
    - **The four answers record what they record today.** AnswerSwitch
      only changes the order on screen: a value typed is "I have it", and
      the status field is unchanged.
    - **Targets and shared counts** are the same fields, asked elsewhere
      (the number's screen, Settings).
    - **AskList** copies one request per role but stamps **each** number
      with its own request and date, as today.
    - **NextStep** reads statuses, efforts (the catalogue's tags), request
      dates, the month and the backup state. All of these exist today, and
      "last visit" is the last-touched date the resume band already uses.
    - **"Your definition" and "Note to self"** stay two fields.
    - **The pre-paint flag** reads the existing storage key and stores
      nothing.
    - **One assumption to confirm:** each "Ask someone" number needs a
      default role for AskList's grouping. Today's "To go and get" already
      groups by role, so we assume the role is stored or derived. If it is
      not, that is the one addition, and it is Antoine's to decide.

## How the measures were taken

`board/measure.cjs` (Playwright, Chromium) opens each
`board.html?screen=…&lang=…` at 1280 × 900, 390 × 844 and 320 × 844. On
each it reads:

- where the tool's element starts on the page;
- its height, and the sheet's;
- the visible focusable controls, inside the tool and in the first
  viewport;
- each control's target, with the system's `::before` extensions, and any
  overlaps;
- the document's scroll width.

It writes `board/measures.js`, which the journey screen reads. Today's
figures are the brief's own table. The board's site header and band are
stand-ins at the production build's heights (72px and 46px).
